# Прошивка под плату v2 — дизайн

Дата: 2026-10-17. Ветка `fw-v2` (от `pcb-v2`).

## Цель

Текущая прошивка (6 лент, CAN MS43, IMU, GyverHub) работает на плате v2, плюс то, что
v2 даёт нового: управление питанием лент с защитой по току, измерение VBAT и опрос MS43
по K-line (DS2) как ещё один источник данных для лент.

Решено с пользователем:

- Поддерживается **только v2**. v1 остаётся на последнем коммите main (поставить тег
  `fw-v1-last` на main перед слиянием). Никаких `#ifdef` под две платы.
- K-line нужна **как источник данных** (rpm/speed/throttle/temp), не для диагностики.
- Ленты — **WS2815** (12 В, протокол как WS2812B).
- microSD — вне этого спека, отдельно потом.

## Железо (из `PCB/v2/gen/model.py`, `PCB/v2/README.md`)

| Что | Факт | Следствие для прошивки |
|---|---|---|
| LED1..6 DATA | GPIO 4, 5, 6, 7, 15, 16 через 74HCT245 | только эти пины, SPST нет |
| I2C | SDA 8, SCL 9 | IMU + разъём EXT |
| LSM6DS3TR-C | 0x6A (SA0 на GND), INT1 → GPIO17 | INT1 пока не используется |
| LED_PWR_EN | GPIO10 → BTS7002 IN, 10k вниз | ленты обесточены, пока пин не HIGH |
| LED_ISENSE | GPIO2 (ADC1), IS через 470 Ω, 1k + 100 нФ, BAT54 на 3V3 | I = V × 22700 / 470 ≈ V × 48.3 А; fault → V упирается в ~3.3 В |
| VBAT_SENSE | GPIO1 (ADC1), 47k/10k + 100 нФ | VBAT = V × 5.7 |
| STATUS_LED | GPIO11 → 1k → LED → GND | HIGH = горит |
| CAN (TJA1051T/3) | TX 18, RX 21, S = GPIO14, 10k вверх на 3V3 | S LOW = normal, HIGH = silent |
| K-line (TJA1027T/20) | RXD → GPIO12, TXD ← GPIO13, SLP_N на 3V3 | UART1; трансивер всегда включён; эхо своей передачи |
| K pull-up | JP2 + 510 Ω на VBAT | без перемычки шина висит, если DME не тянет сама |
| UART0 | 43/44 разъём J3 | Serial остаётся на нативном USB CDC |
| UART2 | 35/36 разъём EXT | не используется |

ADC1 работает вместе с Wi-Fi (в отличие от ADC2), поэтому GPIO1/2 можно читать в любой
момент.

## Часть 1 — перенос

Подход: правим существующие модули на месте, без HAL-слоя.

### pins.h
Полностью по таблице выше. Удаляются `GPS_*`, `SPST*`, `LED_FLASH_PIN`. Добавляются
`LED_PWR_EN_PIN`, `LED_ISENSE_PIN`, `VBAT_SENSE_PIN`, `STATUS_LED_PIN`, `IMU_INT1_PIN`,
`K_RX_PIN`, `K_TX_PIN`.

### Удаление мёртвого кода
`gps_controller/` (нигде не вызывается, GPS на v2 нет) и пустые `telegram_bot.*`.
TinyGPSPlus и FastBot убрать из `lib_deps`, если больше нигде не используются.

### IMU (`imu.cpp`)
Интерфейс `imu.h` (`ImuData`, `imuSetup/Tick/Calibrate`, `imuLateralG`, `imuYawRate`)
не меняется.

- Поиск: ACK на 0x6A (и 0x6B на всякий случай), WHO_AM_I (0x0F) должен быть 0x6A, иначе
  лог и повторная попытка через 5 с.
- Инициализация: CTRL3_C (0x12) = 0x01 (SW reset), подождать, потом CTRL3_C = 0x44
  (BDU + IF_INC); CTRL1_XL (0x10) = 0x48 (104 Гц, ±4 g); CTRL2_G (0x11) = 0x44
  (104 Гц, ±500 °/с).
- Чтение: 14 байт с OUT_TEMP_L (0x20): temp, gyro XYZ, accel XYZ, little-endian.
- Масштабы: accel 0.122 mg/LSB, gyro 17.5 mdps/LSB, temp = raw / 256 + 25.
- Остальное (ФНЧ, счётчик ошибок, «lost», переподключение) как было.
- Оси по умолчанию (по шелкографии, плата лицом вверх, правым краем вперёд): +X сенсора = нос,
  +Y = влево, +Z = вверх. Дефолты `drive.lateralAxis` = +Y (2), `yawAxis` = +Z (4).

### Ленты (`led_control.cpp`)
- Тип в FastLED остаётся `WS2812B` (у WS2815 тот же тайминг), дефолтный `colorOrder` = GRB.
- `setMaxPowerInVoltsAndMilliamps(12, …)` вместо 5.
- Убрать выбор разъёма для 6-й ленты: поле `drive.strip6Out`, select в хабе, ветки в
  `initializeLEDStrips`.

### Питание (новый модуль `power/`)
```
void powerBegin();          // пины, АЦП, ключ выключен
void powerTick();           // из loop(), раз в 10 мс
void powerSetWanted(bool);  // что хотят ленты (master on и т.п.)
void powerResetLatch();     // кнопка в хабе
struct PowerState { float vbat; float ledAmps; bool on; bool latched; String reason; };
extern PowerState power;
```
- VBAT: `analogReadMilliVolts(VBAT_SENSE_PIN) * 5.7`, скользящее среднее (α 0.1).
- Ток: `analogReadMilliVolts(LED_ISENSE_PIN) / 1000 * 22700 / 470`, то же сглаживание.
  Сырое напряжение IS храним тоже, оно нужно для проверки fault.
- Ключ включается, если `wanted && !latched && первый чёрный кадр уже отправлен` (флаг
  выставляет LED-задача после первого `show()`).
- Латч:
  - перегруз: сглаженный ток > `drive.ledMaxAmps` (настройка, по умолчанию 15 А) дольше
    100 мс;
  - fault: сырое IS > 2.8 В дольше 50 мс при включённом ключе (BTS7002 отдаёт I_IS(fault)
    при КЗ или перегреве, напряжение упирается в клэмп).

  При срабатывании ключ выключается, `latched = true`, причина пишется в `sysLog`. Сброс
  только из хаба.
- `wanted` = `drive.masterOn`. Режим «Engine off → Off» ключ не трогает, только гасит
  пиксели: ключ на каждое заглушение дёргать не нужно.

### STATUS_LED
В `power/` (или в `system/`, где проще): горит постоянно до конца `setup()`, потом мигает
1 Гц при нормальной работе и 5 Гц при сработавшем латче.

### CAN
В `main.cpp` поменять только пины (RX 21, TX 18, STB 14). `CANBus::begin` уже ставит STB
в LOW, а LOW для TJA1051 значит normal.

### Хаб
Системная страница: VBAT (В), ток лент (А), ключ on/off/latched + причина, кнопка
«Reset power latch», спиннер «LED max current A» (1..25). Убрать «Strip 6 output».

### Настройки
Поменять букву версии ключа FileData (настройки сбросятся, на новой плате это ничего не
стоит). Новое поле `drive.ledMaxAmps` (float, 15), `strip6Out` удаляется. `canMode`
остаётся как есть, только диапазон в `settings.cpp` расширяется до 0..3 (см. часть 2).

## Часть 2 — K-line DS2

Подход: ещё один режим источника данных `CAN_MODE_DS2 = 3` в существующем `vehicle`.
Ленты и хаб продолжают читать ту же `VehicleData`. В хабе селектор переименовать в
«Data source»: OBD2 CAN / BMW MS43 CAN / Sniffer / BMW MS43 K-line.

При DS2 TWAI-драйвер остаётся в listen-only, но его кадры не декодируются.

### Модуль `kline/`
```
void klineBegin();                                   // UART1, 9600 8E1, RX pull-up
bool klineRequest(const uint8_t* req, size_t len);   // неблокирующий старт запроса
int  klinePoll(uint8_t* resp, size_t cap);           // >0 длина ответа, 0 ждём, <0 ошибка
struct KlineStats { uint32_t tx, ok, timeouts, badCrc, badEcho; float hz; };
```
- Фрейм DS2: `[addr][len][data…][xor всех предыдущих байт]`, `len` = длина всего фрейма.
  Адрес MS43 = 0x12.
- Эхо: TJA1027 возвращает на RXD всё, что сами передали. Первые `len` принятых байт
  сверяются с отправленным запросом (несовпадение → `badEcho`) и отбрасываются.
- Ответ: ждём заголовок `0x12`, читаем `len`, дочитываем фрейм, проверяем xor. Таймаут
  300 мс от конца эха. Пауза между запросами ≥ 10 мс.
- Ничего не блокирует `loop()`: состояние машины крутится в `vehicleTick()`.

### Опрос и расшифровка
- Один статусный запрос по кругу. Какой именно (кандидат: `12 05 0B 03 1F`) и смещения
  rpm / speed / throttle / coolant в ответе берутся при реализации из открытых
  источников по DS2 MS43 (ms4x.net и подобные) с указанием ссылки в коде.
- До проверки на машине все формулы помечены в коде и в README как **непроверенные**.
- `vehicle.lastUpdate` обновляется на каждом удачном ответе, так что существующая логика
  «устарело → 0» работает без изменений.

### Отладка (страница DS2 в хабе)
- Последний сырой ответ в hex, счётчики `KlineStats`, частота ответов.
- Поле «custom request» (hex без xor, xor дописывается сам) + кнопка Send; ответ
  показывается там же и печатается в Serial. Пока висит custom-запрос, циклический опрос
  на паузе.

## Проверка

На столе (USB + 12 В с лабораторного БП, перед этим прозвонить XT60):
1. Лог загрузки: `ready`, нет brownout, причина ресета нормальная.
2. IMU: найден 0x6A, при наклоне платы знаки ax/ay/az совпадают с шелкографией.
3. VBAT в хабе отличается от тестера не больше чем на ±0.2 В.
4. Лента WS2815 на каждом из 6 разъёмов светит правильными цветами, ток в хабе ненулевой
   и растёт с яркостью.
5. Латч: временно поставить `ledMaxAmps` = 0.5, включить белый на полную, ключ должен
   выключиться, светодиод статуса мигать часто, кнопка сброса возвращает ключ.
6. CAN в режиме Sniffer: драйвер поднимается, без шины ошибок шины нет.
7. K-line (JP2 стоит, 12 В подано): запрос уходит, эхо совпадает (`badEcho` = 0), без
   DME дальше таймауты.
8. Обход меню хаба 0..N по HTTP (см. memory про board access), все страницы отвечают.

Только в машине: данные DS2 и CAN, формулы DS2, оси IMU в движении.
